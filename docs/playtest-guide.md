# 《州弈》试玩测试指南

> 文档状态：原型阶段  
> 适用版本：当前本地可玩原型  
> 目的：用一致的方法观察规则理解、地图可读性和核心决策是否成立，而不是证明游戏已经平衡。

## 1. 试玩目标

当前试玩优先回答以下问题：

1. 玩家能否理解“逐州赢家通吃”，而不会只看全盘总面积？
2. 玩家是否理解安全州只提供开局落子权，并非永久归属？
3. 选州阶段是否产生了有意义的取舍？
4. 玩家能否读懂随机区域边界、分值和实时控制信息？
5. 实时阴影是否帮助判断，还是被误认为正式终局比分？
6. 区域翻转是否令人兴奋，还是过于频繁、嘈杂？
7. 对局中是否存在多个合理战略，而不是所有玩家都追逐同一个最高分州？
8. 终局确认是否清楚，死子标记是否符合预期？

当前 AI 棋力较弱，因此试玩结果不能单独用于判断黑白平衡。

## 2. 试玩者类型

记录试玩者的围棋经验，但不需要收集姓名或其他个人信息：

- **A：不了解围棋**：需要先解释气、提子和围地；
- **B：了解基本规则**：能够完成一盘普通围棋；
- **C：有稳定棋力**：能讨论厚势、先手、侵消和死活；
- **D：策略游戏玩家但不熟悉围棋**：适合测试区域制是否容易理解。

不要将不同经验组的结果直接混在一起。新手遇到的规则障碍和熟练玩家发现的战略问题属于不同证据。

## 3. 建议测试环境

- 使用全新页面开始，避免继承上一盘的设置印象。
- 尽量让试玩者自己阅读《游戏说明》，主持人只在卡住时解释。
- 保留棋盘数据叠层开启，除非该场专门比较信息密度。
- 每盘结束后导出棋谱，并记录地图种子。
- 记录游戏版本或测试日期。
- 除非本场就是对比实验，否则不要在同一盘中途改变规则解释。

## 4. 推荐测试流程

不要求每位试玩者完成全部场次。首次测试优先完成场次 A 和 B。

### 场次 A：规则理解

| 设置 | 建议值 |
|---|---|
| 棋盘 | 9×9 |
| 地图 | 四方州固定地图 |
| 安全州 | 开启，每方 1 州 |
| 对手 | 双人同屏，或玩家对快速 AI |
| 数据叠层 | 开启 |

观察重点：

- 是否知道白方先选州、黑方先落子；
- 是否会把安全州理解成永久所有权；
- 是否注意到区域分值；
- 第一次看到区域翻转时是否理解原因；
- 是否知道连续两次停一手才会进入终局确认。

建议完成 1–2 盘。

### 场次 B：核心策略

| 设置 | 建议值 |
|---|---|
| 棋盘 | 13×13 |
| 地图 | 随机版图，标准 8 州 |
| 边界 | 自然 |
| 安全州 | 开启，每方 2 州 |
| 对手 | 优先双人同屏 |
| 数据叠层 | 开启 |

观察重点：

- 选择安全州时考虑了哪些因素；
- 是否出现放弃低价值州、争夺摇摆州或过度防守安全州；
- 玩家是否在已经大幅领先的州继续投入无效棋；
- 地图边界是否能被快速辨认；
- 实时控制是否改变了决策。

建议完成 2 盘，第二盘更换地图种子。

### 场次 C：默认完整体验

| 设置 | 建议值 |
|---|---|
| 棋盘 | 19×19 |
| 地图 | 随机版图，标准 12 州 |
| 边界 | 自然 |
| 安全州 | 开启，每方 2 州 |
| 对手 | 双人同屏或均衡 AI |
| 数据叠层 | 开启 |

观察重点：

- 信息量是否过大；
- 区域战略能否维持到中后盘；
- 是否出现多个同时相关的战场；
- 对局长度和等待时间是否合理；
- 终局时逐州结果能否解释整盘胜负。

这场适合已经理解基本规则的试玩者。

### 场次 D：信息显示对比

使用相同地图种子完成两盘短局：一盘开启数据叠层，一盘关闭。

比较：

- 决策速度；
- 对局后的局势回忆；
- 对实时估算的信任程度；
- 棋盘是否显得拥挤；
- 玩家更喜欢自己判断还是依赖提示。

这属于专项实验，不应与普通试玩数据混合。

## 5. 主持人观察表

每盘记录：

| 字段 | 内容 |
|---|---|
| 测试编号 | 例如 PT-2026-001 |
| 日期与版本 | 日期、提交或版本标识 |
| 试玩者经验组 | A / B / C / D |
| 棋盘与地图 | 尺寸、固定/随机、区域数、风格 |
| 地图种子 | 随机地图必填 |
| 安全州 | 是否开启、每方数量 |
| 控制方式 | 人/人、人/AI、AI/AI |
| 对局长度 | 总手数与大致用时 |
| 结果 | 黑白区域分与胜者 |
| 棋谱文件 | 文件名或存放位置 |

观察事件建议使用时间点或手数标记：

- 第一次主动比较州分；
- 第一次尝试非法操作；
- 第一次误读实时估算；
- 第一次有意识地放弃一个州；
- 第一次为了翻州而改变普通围棋选择；
- 明显困惑、停顿或请求解释；
- 认为胜负已经确定的时刻；
- 实际胜负与玩家预期不一致的时刻。

主持人应记录看到的行为和玩家原话，避免立即解释成设计结论。例如写“玩家连续三次寻找关闭阴影的方法”，优于写“UI太复杂”。

## 6. 赛后反馈问题

### 6.1 不提示答案的理解检查

1. 请用自己的话说明怎样赢得整盘游戏。
2. 安全州为你提供了什么？它是否会永久属于你？
3. 棋盘上的黑白灰色阴影表示什么？
4. 最终比分在什么时候确定？
5. 如果你在一个州已经大幅领先，继续扩大领先有什么价值？

### 6.2 量表题

使用 1–5 分，1 表示非常不同意，5 表示非常同意：

- 我能清楚辨认各州边界。
- 我能理解每个州为什么由某一方领先。
- 我知道下一手应该关注哪些州。
- 选安全州时存在不止一个合理选择。
- 区域分值让我改变了普通围棋中的选择。
- 棋盘信息足够，但没有过度拥挤。
- 区域翻转的频率令人兴奋，而非混乱。
- 终局结果与我对局势的理解基本一致。
- 我愿意再玩一盘不同地图。

### 6.3 开放问题

1. 哪个决定最有趣？为什么？
2. 哪个时刻最困惑？
3. 有没有一个州让你觉得分值与争夺难度明显不匹配？
4. 你是否曾经觉得某方已经无法翻盘？发生在什么时候？
5. 你希望下一盘改变哪个设置？
6. 如果只能删除一个界面信息，你会删除什么？
7. 如果只能增加一个提示，你希望看到什么？

## 7. 问题分类

### 规则理解问题

玩家在阅读说明后仍无法解释或预测规则。

### 信息呈现问题

规则本身可以理解，但边界、标签、颜色或阶段提示让玩家看错状态。

### 平衡问题

玩家理解规则，却认为某个颜色、选州顺序、地图或分值方案具有系统性优势。

### 节奏问题

对局过早失去悬念、长期没有区域翻转，或终局阶段拖延。

### AI问题

AI作出明显不符合当前局面目标的行动。此类问题必须与规则平衡问题分开记录。

### 程序错误

界面状态与合法操作不一致、棋谱不能复现、计分错误或流程卡死。

## 8. 严重程度

- **S0 阻断**：无法完成对局、数据损坏或必现崩溃；
- **S1 严重**：规则结果错误，或正常流程无法继续；
- **S2 明显**：误导决策、重复出现的理解障碍或重要体验问题；
- **S3 一般**：局部不便、措辞或视觉问题；
- **S4 建议**：偏好与未来构想。

程序错误至少附带：地图种子、设置、棋谱、操作步骤和实际/预期结果。

## 9. 试玩结论的使用原则

- 单名玩家的一次意见是线索，不是结论。
- 多人出现相同行为，比多人给出相同评分更有说服力。
- 规则不理解应先检查说明和界面，再考虑修改规则。
- 弱 AI 造成的无聊对局不应直接归因于地图或赢家通吃机制。
- 极端地图既可能是生成错误，也可能是有趣内容；需要结合数据与人工判断。
- 修改一个核心规则后，应重新运行固定基准场次，避免跨版本直接比较。

## 10. 每轮试玩的最低产出

一次正式试玩轮次至少保留：

1. 使用的游戏版本；
2. 完整设置和地图种子；
3. 导出的棋谱；
4. 主持人观察记录；
5. 赛后问题答案；
6. 三条以内最重要的发现；
7. 下一轮准备验证的明确假设。
